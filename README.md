# Рыбинск → Ярославль · 13–14 сентября 2026

Мобильный маршрут для двоих. [Открыть сайт](https://zqaqzqaqsasha.github.io/rybinsk-yaroslavl-2026/).

Статический сайт без сборщика и сторонних UI-зависимостей. Развивает карточки, временную шкалу и офлайн-логику [поездки в Нижний Новгород](https://github.com/zqaqzqaqsasha/nizhny-novgorod-2026). Данные новой поездки созданы отдельно.

## Локальный запуск

```sh
python3 -m http.server 8080
# http://localhost:8080
node --test scripts/test.mjs
```

Нужен HTTP, а не file://. Для тестов и обновления погоды используется Node 24 (без npm install).

## Устройство проекта

- `data/trip.json` — все места, проверенные ссылки, два дня, билеты и инструкция заселения.
- `app.js`, `core.js` — расписание, московское время, ближайший пункт, поезда и локальные отметки.
- `venue-cards.js/css` — карточки в доступном native dialog, без обязательной фотографии.
- `trip-nav.js/css` — одинаковое меню двух поездок, текущая выделена.
- `data/weather.json` — сохранённый актуальный прогноз на два сочетания город/дата.
- `scripts/update-weather.mjs` — проверка и атомарная запись нового прогноза. Ошибка сохраняет старый файл.
- `sw.js` — офлайн-кеш только этого проекта; кеши соседних поездок не удаляются.
- `route.md` — текстовый экспорт, также доступна печать обоих дней / Save as PDF.

Все времена заданы явно с `+03:00`; время устройства не меняет расписание. Дождевой сценарий удалён по просьбе пользователя. Чек-лист, бронь и изменение Tricount-ссылки хранятся только в localStorage с префиксом `ry-2026:v1:`. Никакие бронирования не отправляются.

## Погода и публикация

По уточнению пользователя Яндекс Погода и её API исключены. Источник — [Open-Meteo](https://open-meteo.com/), данные CC BY 4.0. **Секреты и API-ключи не требуются**. Сохраняется архитектура Actions → скрипт → JSON → интерфейс. Браузер читает локальный JSON, не обращается к погодному API.

GitHub Pages: Settings → Pages → Source **GitHub Actions**. Официальный workflow публикует сайт при push, вручную и раз в 6 часов. В рамках сборки обновляется прогноз для двух дней; при недоступности источника используется проверенная копия из репозитория. Автоматическое обновление работает только в окне 30.08–14.09.2026. После поездки сохраняется доступный прогноз; публикация не требует секрета и не ломается из-за истёкших дат. Прогноз, полученный во время workflow, находится в артефакте публикации, а не создаёт автоматические коммиты в main.

Первое открытие дождаться «Готово для офлайн». Кешируются страницы, стили, JS, данные и текстовый маршрут. Карты и сторонние ресурсы требуют сети. При правках кода обновляйте версию кеша в `sw.js`.
